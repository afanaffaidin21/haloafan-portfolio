# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in dark theme to the public site, default-light regardless of OS, with the footer and black contrast blocks flipping to light.

**Architecture:** A semantic token layer replaces the literal grey scale in Tailwind's `@theme`; a `.dark` class on `<html>` overrides those tokens, so components switch without per-component conditional logic. A single client control persists the choice in `localStorage`; a blocking inline script applies it before paint.

**Tech Stack:** Next.js 16.4.6 (App Router), React 19.1.0, Tailwind CSS 4.1.13 (CSS-first `@theme`), Vitest 5.1.0. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-12-dark-mode-design.md`

## Global Constraints

- Default is light even when `prefers-color-scheme: dark`; never read `matchMedia`.
- Storage key is exactly `theme`; values are exactly `"light"` and `"dark"`.
- Dark class lives on `<html>`; `.dark { color-scheme: dark; }`.
- Collapsed nav pill stays 233px; open pill grows 550 → 590px with `max-w-[calc(100vw-24px)]`.
- Legacy scale tokens `--color-f7/fa/f0/de/b8/82/54/2b` are removed once no component uses them. `--color-white`, `--color-black`, `--color-green` remain literal.
- Admin routes (`src/app/(payload)`) are untouched.
- No geometry, typography, motion, or CMS changes.
- Every task ends with a commit.

## Review Focus

1. Muted labels inside a flipped surface (footer, black cards) must stay ≥ 4.5:1 in both themes; the failure looks like grey-on-white washed out.
2. `text-white` sitting on a photo or video must remain literal white and must not be migrated to `invert-ink`.
3. A first-time visitor on a dark OS must get the light theme; a wrong default is visible before any interaction.
4. A reload while in dark mode must paint dark immediately; a light flash is the failure.
5. The nav and footer controls must never disagree about the current theme.

## File Structure

- `src/app/globals.css` — token definitions, `.dark` overrides, body/selection, toggle glyph visibility.
- `src/lib/theme.ts` — storage key, event name, `Theme` type.
- `src/components/theme-toggle.tsx` — the client control (single component, two mounts).
- `src/app/(site)/layout.tsx` — no-flash script, `<html>` attributes.
- `src/components/nav.tsx`, `src/components/footer.tsx` — placement and width.
- `src/components/*.tsx` (remaining) — utility-class migration; `icons.tsx` logo fills.
- `tests/lib/*` — untouched; the existing suite must keep passing.

### Task 3: Toggle, persistence, and no-flash wiring

**Files:**
- Create: `src/lib/theme.ts`
- Create: `src/components/theme-toggle.tsx`
- Modify: `src/app/globals.css` (glyph visibility)
- Modify: `src/app/(site)/layout.tsx`
- Modify: `src/components/nav.tsx`
- Modify: `src/components/footer.tsx`

**Interfaces:**
- Consumes: tokens from Task 1.
- Produces:
  - `export const THEME_KEY = "theme"` — `string`
  - `export const THEME_EVENT = "themechange"` — `string`
  - `export type Theme = "light" | "dark"`
  - `export function ThemeToggle({ className }: { className?: string })` — client component

- [ ] **Step 1: Add the shared constants**

`src/lib/theme.ts` contains exactly:

```ts
export const THEME_KEY = "theme";
export const THEME_EVENT = "themechange";
export type Theme = "light" | "dark";
```

- [ ] **Step 2: Create `ThemeToggle`**

Client component. State comes from `useSyncExternalStore`:

- `subscribe(cb)`: add `window.addEventListener(THEME_EVENT, cb)`, return the remover.
- `getSnapshot()`: `document.documentElement.classList.contains("dark")`.
- `getServerSnapshot()`: `() => false`.
- Click: `next: Theme = isDark ? "light" : "dark"`, then
  `document.documentElement.classList.toggle("dark", next === "dark")`,
  `localStorage.setItem(THEME_KEY, next)` inside `try`, then
  `window.dispatchEvent(new Event(THEME_EVENT))`.
- Markup: one `<button type="button" aria-label="Toggle dark mode" aria-pressed={isDark} className={className}>` containing a sun `<svg className="tt-sun">` and a moon `<svg className="tt-moon">`, both 16×16, `stroke="currentColor"`, `fill="none"`.

- [ ] **Step 3: Add glyph visibility CSS**

In `globals.css`:

```css
.tt-moon { display: none; }
.dark .tt-sun { display: none; }
.dark .tt-moon { display: block; }
```

- [ ] **Step 4: Add the blocking script**

In `<head>` of `src/app/(site)/layout.tsx`, before `<body>`, interpolating the constant so the key cannot drift:

```tsx
<script
  dangerouslySetInnerHTML={{
    __html: `try{if(localStorage.getItem("${THEME_KEY}")==="dark")document.documentElement.classList.add("dark")}catch(e){}`,
  }}
/>
```

Add `suppressHydrationWarning` to `<html lang="en">`.

- [ ] **Step 5: Place it in the nav**

In `nav.tsx`, render `<ThemeToggle />` after the "Email me" link inside the animated cluster, `style={{ opacity: open ? 1 : 0, transitionDelay: open ? "0.5s" : "0s" }}`. Change the open width from 550 to 590 and add `max-w-[calc(100vw-24px)]` to the pill.

- [ ] **Step 6: Place it in the footer**

In `footer.tsx`, render `<ThemeToggle />` next to the social links, inheriting `text-invert-ink` so its strokes follow the footer.

- [ ] **Step 7: Verify default-light under OS dark**

With `localStorage.removeItem("theme")`, emulate `prefers-color-scheme: dark` and reload. Expected: `document.documentElement.classList.contains("dark") === false` and the body is `rgb(250, 250, 250)`.

- [ ] **Step 8: Verify persistence and sync**

Click the nav toggle. Expected: page turns dark, `localStorage.theme === "dark"`, and the footer control reports `aria-pressed="true"`. Reload — expected: still dark, no light frame. Click the footer toggle — expected: light, `aria-pressed="false"` in the nav too, `localStorage.theme === "light"`.

- [ ] **Step 9: Verify no flash and geometry**

Run `curl -s http://localhost:3400/ | grep -n 'localStorage.getItem("theme")'` — expected: a match inside `<head>`, before the first `<body` occurrence. Measure the pill: collapsed 233px; open 590px at 1440; open width never exceeds `viewportWidth - 24` at 375px. Confirm the page does not scroll horizontally at 375px.

- [ ] **Step 10: Full build and suite**

Run: `npx next build` then `npx vitest run`.
Expected: build success; the existing suite passes unchanged.
